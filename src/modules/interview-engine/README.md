# Interview Engine 设计说明

## 状态转移设计

- `self_intro -> technical`：自我介绍后必须进入技术面，保证面试主流程统一。
- `technical -> project_deep`：连续答对 3 题后，说明技术基础稳定，进入项目深挖验证真实经验。
- `technical -> behavioral`：连续答错 3 题后，技术深度不足，切换行为面更全面评估候选人。
- `project_deep -> coding`：项目深挖满意后，用代码考核验证实现能力。
- `behavioral -> q_and_a`：行为面结束后进入反问环节，完成面试闭环。
- `coding -> q_and_a`：代码面结束后进入反问环节。
- `q_and_a -> ended`：反问结束后收尾。

## 设计原则

1. 先规则后 AI：核心转移规则硬编码，AI 只做补充判断，避免流程漂移。
2. 分阶段评估：不同阶段关注点不同，避免单一评分误导。
3. 可解释性：所有转移都能从分数、连续表现和历史消息中追溯。
4. 抗重复：问题生成做相似度去重，减少重复提问。
5. 可降级：AI 格式错误时自动回退到规则和默认输出。
